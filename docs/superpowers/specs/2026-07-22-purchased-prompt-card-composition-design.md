# 구매한 프롬프트 카드 데이터 조합 설계

## 배경

마이페이지의 구매한 프롬프트 탭은 주문 조회 결과만으로 카드를 만들고 있다. 상품 배치 조회 API가 없던 시점에는 상품의 최신 제목, 썸네일, 모델, 가격, 평점, 판매 수와 판매자 정보를 완성할 수 없었다.

현재 다음 API가 준비되어 있다.

- `POST /api/v2/products/orders`: 상품 ID 목록으로 구매 카드용 상품 정보를 조회한다.
- `POST /api/v2/users/order-products`: 상품 응답의 판매자 ID 목록으로 판매자 이름을 조회한다.

## 목표

- 주문 목록에 상품 정보와 판매자 이름을 조합해 구매한 프롬프트 카드를 완성한다.
- 일부 연동 실패가 구매 목록 전체 실패로 이어지지 않게 한다.
- 페이지 컴포넌트에서 데이터 조합 규칙을 분리해 단위 테스트할 수 있게 한다.

## 데이터 흐름

1. 주문 API로 구매 가능한 주문 상품을 조회한다.
2. 주문을 기존 카드 형태로 변환하고 상품 ID를 수집한다.
3. `/products/orders`에서 상품 정보를 배치 조회한다.
4. 상품 응답의 판매자 ID를 `/users/order-products`로 배치 조회한다.
5. 상품 ID와 판매자 ID를 기준으로 주문 카드에 상품·판매자 정보를 조합한다.
6. 완성된 카드 목록을 구매 탭 상태에 반영한다.

배치 요청은 기존 `splitUniqueIds`를 사용해 API 제한인 요청당 30개를 지킨다.

## 필드 조합 규칙

상품 응답에서 다음 필드를 우선 사용한다.

- `title`
- `thumbnailUrl`
- `model`
- `amount`
- `averageRating`
- `salesCount`
- `productType`
- `sellerId`

판매자 응답은 `sellerId`로 찾아 `seller`에 반영한다. 판매자 이름이 없거나 판매자 조회가 실패하면 기존 카드의 `seller` 값을 유지한다.

주문 식별자, 주문 상품 식별자, 구매일, 다운로드 여부, 환불 가능 여부와 같은 주문 상태 필드는 주문 응답을 기준으로 유지한다.

## 실패 처리

- 상품 조회 실패: 기존 주문 정보로 만든 카드를 그대로 표시한다.
- 판매자 조회 실패: 상품 정보는 반영하고 판매자명은 기존 fallback을 유지한다.
- 특정 상품 또는 판매자가 응답에서 누락: 해당 카드만 기존 값으로 보완한다.
- 주문 조회 실패: 현재 화면 동작을 유지한다.

## 코드 구조

- `lib/sellers.ts`: 구매 상품 판매자 이름 배치 조회 함수 추가
- `lib/orderAdapters.ts`: 주문 카드에 상품·판매자 데이터를 조합하는 순수 함수 추가
- `app/mypage/page.tsx`: API 호출 순서와 상태 반영만 담당
- `lib/orderAdapters.test.ts`: 필드 조합, 응답 누락, 판매자명 fallback 테스트 추가
