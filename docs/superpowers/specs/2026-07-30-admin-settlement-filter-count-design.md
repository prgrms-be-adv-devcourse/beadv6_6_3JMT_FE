# 관리자 정산 상태 필터 건수 수정 설계

- 작성일: 2026-07-30
- 대상 화면: `/admin/settlements`

## 1. 문제

관리자 정산 화면은 `GET /api/v2/admin/settlements/summary` 응답을 상단 요약 카드와
상태 필터 건수에 함께 사용한다.

요약 API는 화면 상단 카드 전용 계약이라 다음 네 버킷만 반환한다.

- `WAITING`: `WAITING`과 `APPROVAL_ON_HOLD` 합계
- `APPROVED`: `APPROVED`와 `PAYOUT_REQUESTED` 합계
- `PAYOUT_ON_HOLD`
- `PAID`

따라서 `PAYOUT_REQUESTED` 정산이 있어도 프론트가 해당 상태를 직접 찾으면 값이 없어서
0으로 표시된다. 반면 목록 API의 `status=PAYOUT_REQUESTED` 필터는 실제 상태에 적용되므로
필터를 누르면 정산이 조회된다. `CANCELLED`도 요약 API에서 제외되어 전체 필터 건수와
실제 상태별 합계가 달라질 수 있다.

## 2. 목표와 제외 범위

### 목표

- 상태 필터의 7개 건수를 실제 주간 정산 상태 기준으로 표시한다.
- 선택한 정산 월이 있으면 해당 월 범위의 상태 건수를 표시한다.
- 상단 네 개 요약 카드의 기존 금액·건수 의미를 유지한다.
- 상태 필터 목록의 판매자·월 그룹 조회 방식은 유지한다.

### 제외 범위

- 백엔드 API 계약 변경
- 월별 목록을 주간 정산 행 목록으로 변경
- 상단 요약 카드의 버킷 정책 변경
- 현재 페이지에 내려온 월별 목록이나 상세 목록을 이용한 프론트 재집계

## 3. 접근 방식

### 채택: 주간 정산 목록 API의 `statusCounts` 사용

`GET /api/v2/admin/settlements/weeks`는 선택 월 전체를 기준으로 7개 상태의
`statusCounts`를 항상 반환한다. 프론트는 이 응답을 변환하는 전용 함수를 추가하고,
상태 필터 건수에는 이 값만 사용한다.

건수 조회 시 목록 항목 자체는 사용하지 않으므로 최소 페이지 크기로 요청한다. 선택 월은
`settlementMonth`로 전달하고, 특정 상태는 전달하지 않아 7개 상태 전체 기준을 유지한다.

상단 요약 카드는 기존 `GET /admin/settlements/summary`를 계속 사용한다. 두 응답 상태를
별도로 보관해 카드 버킷과 필터 상태 건수의 의미가 섞이지 않게 한다.

### 검토한 대안

1. 백엔드 요약 응답에 7개 상태 건수를 추가할 수 있지만 백엔드 변경과 배포가 필요하며,
   기존 네 카드 계약과 필터 계약이 한 응답에 다시 결합된다.
2. 현재 월별 목록이나 펼친 상세에서 건수를 계산하면 페이지네이션과 미조회 상세 때문에
   전체 건수를 보장할 수 없다.

## 4. 데이터 흐름

1. 화면 진입 시 요약 카드, 상태 건수, 월별 목록을 병렬 조회한다.
2. 월 필터가 바뀌면 세 요청 모두 같은 `settlementMonth` 기준으로 다시 조회한다.
3. 상태 필터만 바뀌면 월별 목록은 선택 상태로 조회하고, 요약 카드와 상태 건수는 선택 월
   전체 기준으로 갱신한다.
4. 정산 액션 후 상세, 월별 목록, 요약 카드, 상태 건수를 다시 조회한다.
5. 상태 건수 조회가 실패하면 이전 또는 임의의 0을 사실처럼 표시하지 않고 빈 건수 상태로
   초기화한다. 기존 화면의 숫자 표시 계약을 유지하기 위해 UI에는 0으로 표시하되, 목록
   조회 결과를 건수로 추정하지 않는다.

## 5. 코드 경계

- `lib/settlementContracts.ts`
  - 주간 정산 목록 응답에서 `statusCounts`를 정규화하는 순수 변환 함수를 제공한다.
- `lib/settlements.ts`
  - 주간 정산 상태 건수 조회 함수를 제공한다.
- `app/admin/settlements/_components/AdminSettlementsView.tsx`
  - 요약 카드 상태와 필터 건수 상태를 분리한다.
  - 필터 배지는 7개 상태 건수의 합계를 `전체`로 사용한다.

## 6. 테스트

구현 전 회귀 테스트를 먼저 추가하고 현재 코드에서 실패하는 것을 확인한다.

- 주간 정산 응답의 7개 `statusCounts`를 보존하고 숫자로 정규화한다.
- `PAYOUT_REQUESTED`와 `CANCELLED`가 독립된 상태 건수로 유지된다.
- 전체 건수는 7개 상태 건수 합계로 계산할 수 있다.
- 기존 월별 목록·상세 변환 테스트는 계속 통과한다.

최종 검증은 관련 `node:test`, 전체 테스트, ESLint, Next.js 빌드 순서로 수행한다.

## 7. 완료 기준

- 지급 신청 정산이 4건이면 `지급 신청 4`로 표시된다.
- `승인` 건수에 지급 신청 건수가 합쳐지지 않는다.
- 취소 건수가 `취소`와 `전체`에 반영된다.
- 월 필터와 정산 액션 후 필터 건수가 최신 상태로 갱신된다.
- 상단 네 개 요약 카드는 기존 의미와 값을 유지한다.
