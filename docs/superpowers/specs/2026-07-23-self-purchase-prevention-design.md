# 셀프 구매 방지 프론트엔드 설계

## 목표

로그인 사용자의 ID와 상품 판매자 ID가 같으면 상세 페이지와 체크아웃에서 주문 진입을 막고, 백엔드의 셀프 구매 거부 응답도 사용자에게 그대로 안내한다.

## 데이터 흐름

- 상품 상세 응답의 `sellerId`를 로그인 사용자의 `user.id`와 비교한다.
- 단건 구매 스토어와 장바구니 모델에서 `sellerId`를 보존해 체크아웃까지 전달한다.
- 체크아웃은 주문 상품 중 하나라도 셀프 상품이면 전체 주문을 차단한다.
- 판매자 ID가 없는 구형 로컬 데이터는 백엔드 검증에 맡기고 기존 구매 흐름을 유지한다.

## UI 동작

- 본인 상품의 구매 버튼은 비활성화하고 `본인 상품은 구매할 수 없어요`를 표시한다.
- 유료 본인 상품의 장바구니 버튼도 비활성화한다.
- 이벤트 핸들러에서도 같은 조건을 검사해 프로그래밍 방식 호출을 방어한다.
- 체크아웃에서는 결제 버튼을 비활성화하고 동일한 안내 문구를 표시한다.

## 오류 처리

- 백엔드 오류 메시지가 있으면 체크아웃의 기존 오류 정규화 경로로 표시한다.
- 서버 메시지가 없는 경우 기존 주문 실패 안내를 유지한다.

## 테스트

- 공통 셀프 구매 판별 함수의 단건·다건·누락 ID 사례를 검증한다.
- 장바구니 응답 변환 시 `sellerId`가 유지되는지 검증한다.
- 백엔드 셀프 구매 오류 메시지가 체크아웃 오류로 유지되는지 검증한다.
- 기존 주문·장바구니 테스트와 Next.js 빌드를 회귀 검증한다.

## 제외 범위

- 백엔드 주문 정책과 에러 코드 구현
- 기존 셀프 주문 데이터 정리
- 컴포넌트 구조의 대규모 리팩터링
